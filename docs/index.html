a laravel observability teaching platform

Follow an alert to the log line that caused it.

Meterly is a small, usage-metered API built to demonstrate the loop most observability tutorials skip: starting from a firing alert, narrowing to the exact trace, and landing on the log line that explains it. One trace ID, three systems, one click each.

the acceptance test

Click a bucket, land on the truth

This is the actual verified path from a real incident run, not a mockup: an alert fires, a trace resolves it, a log line confirms it.

metric

The traffic simulator scripts a 90% error rate on the stubbed fraud-check dependency. Two minutes later, HighUsageEndpointErrorRate fires: 37.7% of /api/usage requests are failing, sustained above the 10% threshold for a full two minutes so a single spike can't trip it.

trace

Grafana's Tempo panel resolves the alert's trace ID directly. Both spans, the HTTP request and the fraud-check call beneath it, show STATUS_CODE_ERROR, with the exact exception message attached to the failing span.

log

The same trace ID is a real Loki label, not just a JSON field, so Tempo's trace-to-logs link returns the exact line: Fraud check failed for tenant 47. Query Loki by that ID from either direction and you get the same row back.

seven chapters

What it teaches, in the order it teaches it

Each lesson has a visible payoff in the running system, not just a paragraph explaining the concept.

01

Three stores, three tradeoffs

Why metrics, logs, and traces live in separate systems, and what each one costs you in detail versus retention.

02

Instrumenting Laravel

Middleware counters, a latency histogram, and the line between what belongs on a metric label and what belongs on a log field.

03

Cardinality

A tenant ID is safe on a metric because the set of tenants is bounded. A request ID is not, and will take Prometheus down with it.

04

The correlation triangle

Exemplars, Grafana derived fields, and span-to-log links, wired so a trace ID means the same thing in all three systems.

05

Alerts people won't mute

A sustained-rate threshold instead of a single-spike trigger, plus absence alerting for a job that quietly stops running.

06

Dashboards as code

The dashboard and the two alert rules are provisioned from files in the repo. Nothing here was configured by clicking.

07

Reading it under load

A diurnal traffic simulator with one scripted incident, used as a live test that the alerts actually catch what they claim to.
